# SEO, AEO and GEO Standards

The brief always overrides these defaults. Where it is silent, apply these.

## On-page SEO

| Element | Rule |
|---|---|
| SEO title | ≤ 60 characters, primary keyword near the start, no brand stuffing. Use the brief's title if given and report its length. |
| Meta description | 140–160 characters. Contains the primary keyword or a close variant, and states the reader benefit plainly. |
| H1 | One only. Contains the primary keyword. May differ from the SEO title. |
| URL | Never changed for existing pages. |
| Primary keyword | In the title, H1, first 100 words (inside the definition) and exactly one H2/H3 where it reads naturally. After that, use it only where natural. Never force exact-match repetition. |
| Secondary keywords | Each appears at least once, in a heading or body sentence where it fits. Variants (life cycle / lifecycle) are covered by natural use, not by repetition. |
| Headings | Descriptive, matching how people search ("What is…", "How to…", "X vs Y"). No clever or vague headings. H3s nest logically under H2s. |
| Internal links | Use only links from the registry or brief that are marked verified. Use descriptive anchors and place them mid-paragraph where the concept is discussed, not in a "related posts" dump. Pillar pages link to every spoke; spokes link up to the pillar and to 1–2 sibling spokes. Never link to a URL with the anchor of a query it doesn't own. |
| External links | 2–5 authoritative, dated sources (standards bodies, vendors' primary docs, research). Never link to a direct competitor's blog as a source unless the brief says so. |
| Images | Each diagram or table has a purpose. Supply an alt-text suggestion for each planned image. |

## AEO (answer engines: AI Overviews, ChatGPT, Perplexity, Claude, Gemini)

1. **Answer-first definition** directly under the H1: 40–60 words, self-contained, beginning with "<Primary term> is…". It must be quotable verbatim without its surrounding context.
2. **Every H2 opens with a 1–3 sentence answer** to the question the heading implies. Elaboration comes after.
3. **Comparison and process content goes in tables.** Answer engines lift tables and ordered lists cleanly.
4. **A stand-alone summary block** (an "In short" or "Key takeaways" box of 3–5 bullets) near the top or end that makes sense with no other context.
5. **FAQ** questions are phrased the way people type or ask them, not as repeated section headings. Each answer is 40–80 words and self-contained, with no "as mentioned above".
6. **Define each acronym once**, at first use (e.g. "Product Data Management (PDM)").
7. **Consistent terminology.** Choose one name per concept and keep to it. If the brief notes a variant spelling, mention it once.

## GEO (being cited and correctly represented by LLMs)

- State **entity relationships** explicitly: "X is a type of Y", "X differs from Y in…", "X is used by Z to…".
- Show **evidence of first-hand experience**: specific decisions, trade-offs and mistakes from the author's practice (from the interview). Mark these clearly as the author's experience.
- **Date sensitive claims** ("as of 2026") and cite them.
- Add an **author byline and bio** from the configured bio source, and an "Updated <date>" line.
- No keyword-stuffed "AI-friendly" phrasing. Clear prose beats patterns.

## Length

Use the brief's range. Without one: pillar pages 2,500–4,000 words, spokes 1,200–2,200. Cut sections that don't earn their place; never pad.
